04 / HOW I WORK

I care about the
why, not just the fix.

01

Evidence before assumptions

I read the implementation, reproduce the failure and check the actual system response before deciding what a test should expect.

02

Make failures visible

I avoid hiding errors just to make a test suite green. Cleanup should report failures and verify the system returns to a known state.

03

Simulate, then validate on hardware

Namespaces, veth pairs and tc netem let me repeat network failures safely before moving to modem and node validation.

04

Leave a useful trail

Design notes, test evidence and decision logs make it easier for teammates to review work and continue from it.
